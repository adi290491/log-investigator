## Root cause

The payments deploy `v2.14.0` at 2026-10-21T14:02:00Z (change: "reduced DB pool size 50 -> 5") shrank the payments
DB connection pool from 50 to 5. Normal load uses 5-15 connections, so the pool saturates and charges
fail waiting for a connection. The failure cascades up the chain gateway -> orders -> payments -> DB:
orders times out calling payments, and gateway returns 502/503 to clients.

Remediation: roll back payments to the previous version or restore the pool size to 50.
